# 插件安全模型

本文说明 Hanabi 插件的信任边界、当前保护措施和发布者责任。安装插件等同于允许第三方程序以当前用户身份运行。

> [!WARNING]
> Hanabi API v1 不提供操作系统级沙箱。插件可以执行其运行账户有权执行的操作，`permissions` 目前不是强制访问控制。

## 信任边界

| 组件 | Hanabi 提供的保证 | 不提供的保证 |
| --- | --- | --- |
| `plugin.json` 校验 | 格式、版本、路径和部分 UI 结构有效 | 插件业务行为安全 |
| 包哈希 | 下载内容与索引记录一致 | 索引发布者可信 |
| Ed25519 签名 | 包由对应私钥签发且未被修改 | 签发者代码无恶意 |
| 外部进程 | 插件崩溃通常不会直接破坏 Flutter 进程 | 文件、网络和进程权限隔离 |
| `permissions` | 向用户和审核者声明预期能力 | 阻止未声明操作 |

## 当前保护措施

### 安装路径

宿主与校验器会拒绝：

- `entry`、`icon` 和工作目录中的绝对路径或 `..`；
- 不存在的入口与工作目录；
- 使用 `HANABI_` 前缀伪造宿主环境变量；
- 不受支持的清单/API 主版本；
- 无效或重复的 UI 控件 ID 等结构问题。

这些检查降低误配置和简单目录穿越风险，不构成恶意代码沙箱。

### 商店完整性

商店安装顺序：

1. 下载插件包；
2. 如果索引提供 `hash`，校验 SHA-256；
3. 如果索引提供 `signature` 和 `signingKeyId`，校验 Ed25519 签名；
4. 解压到临时目录；
5. 校验包内 `plugin.json`；
6. 使用回滚目录替换已安装版本。

签名格式见[商店签名约定](PLUGIN_STORE_SIGNATURE_CN.md)。

### 进程协议

宿主校验插件退出码、JSON-RPC 版本、响应 ID 和 `result`/`error` 结构。调用超时后会终止插件进程。

## 插件作者责任

### 最小权限

只声明和使用必要能力：

- 不需要网络的插件不要声明或访问网络；
- 把持久文件限制在 `HANABI_PLUGIN_DATA_DIR`；
- 不把下载路径当作可执行命令；
- 避免使用 shell 字符串拼接，优先使用参数数组；
- 外部命令和依赖版本应固定并在 README 中说明。

### 输入验证

所有宿主参数都应按不可信输入处理，尤其是：

- URI、文件名和保存目录；
- HTTP headers、Cookie 和 Referer；
- `pluginData` 中的旧版本状态；
- UI 文本输入和自定义按钮动作；
- 远程下载服务返回的数据。

验证类型、长度、允许的 scheme 和最终文件路径。不要仅通过字符串前缀判断目录归属。

### 敏感信息

- 不把 Cookie、Token 或完整请求头写入 `stdout`、`stderr` 或持久日志。
- 不把密钥存入 `pluginData` 或 `plugin.json`。
- 必须持久化凭据时，使用操作系统凭据库；当前 SDK 不封装凭据库。
- 错误响应只返回定位问题所需的信息，不返回堆栈、环境变量或本机绝对目录。

### 更新与依赖

- 使用语义化版本并维护变更日志。
- 对依赖执行漏洞扫描并固定可重现版本。
- 发布包一旦公开，不要在相同版本号下替换内容。
- 私钥只用于 CI 签名，不提交到插件仓库或构建产物。

## 市场维护者责任

- 只从来源声明中的固定仓库和路径构建；
- 审核 `permissions`、入口脚本、外部下载和进程启动；
- 在隔离的 CI 环境重建插件包；
- 生成 SHA-256，并对正式渠道使用 Ed25519 签名；
- 保留版本、下架和密钥轮换记录；
- 拒绝把凭据、私钥或未声明二进制文件打入包中。

## 服务器部署建议

- 仅通过 HTTPS 发布索引和插件包；
- 对索引设置短缓存，对不可变版本包设置长缓存；
- 插件包 URL 应包含插件 ID 和版本；
- 禁止相同 URL 的内容静默变化；
- 保留历史包用于回滚，但在索引中标记已撤回版本；
- 对下载日志和对象存储权限使用最小授权。

建议响应头：

```text
Content-Type: application/json; charset=utf-8        # 商店索引
Content-Type: application/zip                        # 插件包
X-Content-Type-Options: nosniff
```

## 发现安全问题

安全报告至少应包含：

- 受影响的 Hanabi 与插件版本；
- 攻击前提和最小复现；
- 是否需要已安装/已启用插件；
- 可能访问的数据和权限范围；
- 建议的临时缓解措施。

公开披露前，应先让维护者有时间撤回商店条目、轮换签名密钥或发布修复版本。
